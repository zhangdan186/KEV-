# 统一输出标准

## 1. 目录

```text
outputs/
├── validation/
├── prepared/
├── tables/
├── queries/
├── figures/
├── html/
├── ml/
├── logs/
└── manifests/
```

程序必须自动创建目录，禁止向项目根目录散落产物。

## 2. 通用格式

### CSV

- 编码：`utf-8-sig`；
- 分隔符：`,`；
- `index=False`；
- 换行：平台原生写入、Git中不追踪运行产物；
- 浮点：`%.8f`；
- 日期：`YYYY-MM-DD`；
- 月份：`YYYY-MM`；
- 布尔：`True/False`；
- 缺失值：空单元格；
- 比例：小数 `[0,1]`，禁止写`12%`；
- `cwes`：紧凑JSON数组字符串，如`["CWE-79","CWE-89"]`。

### JSON

- UTF-8；
- `ensure_ascii=False`；
- 缩进2空格；
- 时间戳使用ISO 8601 UTC，例如`2026-08-06T07:00:00Z`。

### 图表

- PNG，300 DPI；
- 标题、轴标签、单位、图例完整；
- 不在图表中写超出数据支持范围的因果结论；
- 图表函数返回Figure，保存由统一exporter完成；
- 文件名全小写蛇形命名。

### HTML

- 可离线打开；
- 必须包含标题、指标解释和数据口径；
- 不依赖在线地图或外部CDN才能完成核心展示。

## 3. 排序与列顺序

每个输出的列顺序和排序均由`contracts/output_registry.yaml`冻结。禁止依赖`groupby`或集合的默认顺序。

## 4. 比例与精度

- CSV保留8位小数；
- 报告/PPT通常显示为百分比并保留2位小数；
- 计数为整数；
- CR5、CR10、HHI保存8位小数；
- 报告中显示的数值必须来自输出文件，不得手工重新计算后产生差异。

## 5. 覆盖与可复现性

- 默认允许覆盖同名正式产物，保证路径稳定；
- 每次运行额外生成`manifests/run_manifest.json`，记录输入SHA256、契约版本、依赖版本、产物SHA256、行数和列名；
- 随机过程统一使用`random_seed=20260806`；
- 同一输入、代码和配置应生成一致的CSV内容和排序。

## 6. 禁止输出

- 不得生成字段语义错误的“攻击次数”“披露数量”“未被勒索利用”等表头；
- 不得输出`vendor_risk_score`或“最不安全厂商”一类无题目依据的结论；
- 不得把CWE空列表填成伪编码；
- 不得在正式表中混用百分数文本和小数比例。
